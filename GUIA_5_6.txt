GRINGAS TROCA — PASSO 5.6
BANCO ONLINE + FOTOS NA NUVEM + LOGIN ADMINISTRATIVO

O QUE ESTA VERSÃO FAZ
• Continua funcionando em modo local enquanto a nuvem não está configurada.
• Depois de conectar o Supabase:
  - avaliações são gravadas no banco;
  - fotos sobem para Storage privado;
  - admin.html exige login;
  - painel pode ser aberto em outro computador/celular;
  - alterações de status/valor aprovado voltam para a nuvem;
  - upgrade do cliente fica vinculado ao mesmo código GT.
• A estrutura já possui store_id e tabela de membros, preparando multiempresa no futuro.

PASSO A PASSO PARA LIGAR A NUVEM

1. CRIE UM PROJETO NO SUPABASE
   Entre em https://supabase.com e crie um projeto.
   Guarde a senha do banco em local seguro.

2. RODE O SQL
   No Supabase: SQL Editor → New query.
   Abra o arquivo SUPABASE_SETUP.sql deste pacote.
   Copie tudo, cole e clique Run.

3. PEGUE URL E ANON KEY
   No Supabase procure Project Settings / API.
   Você precisa de:
   • Project URL
   • anon/public key (ou publishable key equivalente para navegador)
   NÃO use service_role no site.

4. EDITE config.js
   Abra config.js com um editor de texto.
   Troque:
   COLE_AQUI_SUA_SUPABASE_URL
   COLE_AQUI_SUA_SUPABASE_ANON_KEY

   Não altere o storeId nesta fase.

5. CRIE O LOGIN ADMINISTRATIVO
   No painel Supabase → Authentication → Users.
   Crie um usuário para você com e-mail e senha.
   Na primeira vez que esse usuário entrar no admin.html,
   o sistema tentará torná-lo automaticamente o primeiro OWNER da Gringas.

6. TESTE
   • Abra index.html e faça uma nova avaliação.
   • Abra admin.html.
   • Faça login.
   • A avaliação deve aparecer, inclusive as fotos.
   • Mude status/valor aprovado.
   • Atualize o painel; a alteração deve continuar lá.

IMPORTANTE SOBRE TESTAR ARQUIVO LOCAL
O browser pode bloquear alguns recursos externos quando você abre index.html diretamente como file://.
Se isso ocorrer, o projeto já está pronto para publicação no Passo 5.7, ou você pode testar usando um servidor local simples.

SEGURANÇA
• A anon key é pública por design e fica protegida pelas políticas RLS do banco.
• NUNCA coloque service_role em config.js.
• O visitante pode CRIAR avaliação, mas não pode ler avaliações de outras pessoas.
• O bucket de fotos é privado.
• Usuários administrativos autenticados só leem dados se forem membros da loja.
• Antes de vender como SaaS, adicionaremos proteção antispam/CAPTCHA e políticas multiempresa ainda mais restritas.
